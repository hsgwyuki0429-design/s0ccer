# デプロイ

友達とオンラインで遊ぶには、**ゲームサーバーをどこかに常駐させる**必要がある。
クライアント（GitHub Pages）は静的ファイルなので、サーバーの機能は持てない。

```
[スマホ / PC] ──https──> GitHub Pages（クライアント）
      └────────wss──────> どこかのホスティング（ゲームサーバー）
```

## 全体の流れ

1. サーバーをどこかにデプロイして、`wss://...` の URL を得る
2. GitHub リポジトリの **Variables** に `SERVER_URL` としてその URL を設定する
3. Pages を再デプロイすると、以降は自動でそのサーバーに繋がる

**2 を設定しなければ、Pages はこれまでどおりオフライン（単独プレイ）で動く。**
サーバーを止めてもページが壊れることはない。

## 1. サーバーをデプロイする

リポジトリ直下の `Dockerfile` がそのまま使える。Node の型ストリッピングで
`.ts` を直接実行しているのでビルド手順はなく、本番の依存は `ws` ひとつだけ。

### 選択肢

| | 長所 | 短所 |
|---|---|---|
| **Render** | ブラウザだけで完結する。無料で始められる | 日本リージョンなし（最寄りはシンガポール）。無料プランはアイドルで停止する |
| **Fly.io** | 東京リージョンがある | CLI が要る。無料枠は要確認 |

以下は **Render** の手順。Fly.io を使う場合は `fly.toml` を用意してあるので
`fly launch --no-deploy` → `fly deploy` でよい。

### Render の手順

1. https://dashboard.render.com/ で **New → Blueprint**
2. このリポジトリを選ぶ。`render.yaml` が自動で読まれる
3. **Apply** を押すと、Dockerfile からビルドされてデプロイが始まる（初回は数分）
4. できあがった URL は `https://s0ccer-server.onrender.com` の形

> **`render.yaml` の `branch` を確認すること。** 既定では作業ブランチ
> （`claude/online-soccer-game-m5lxvu`）を指している。`main` にマージしたら
> `branch: main` に書き換える。ここがズレていると、古いコードがデプロイされる。

### 無料プランのアイドル停止について

Render の無料プランは、**約15分アクセスが無いとインスタンスが停止する。**
次にアクセスがあると起動し直すが、**1分近くかかる。**

クライアント側はこれを前提に作ってある。

- 接続に失敗しても諦めず、間隔を空けて**最大8回まで繋ぎ直す**（合計70秒ほど）
- その間、画面には `サーバー起動中… (3/8)` と出る
- 起動が完了すると**自動でオンラインに切り替わる**
- サーバーが再起動しても、**同じパーティコードのまま復帰する**

なので「遊ぶときにページを開いて1分待つ」だけでよい。せっかちなら、先に
`https://s0ccer-server.onrender.com/health` をブラウザで開いて起こしておく。

> **常時起動させたい場合**: 外部から定期的に `/health` を叩けば止まらないが、
> 無料枠の 750 インスタンス時間/月をほぼ使い切る（1か月は約744時間）。
> それなら有料プラン（$7/月〜）にしたほうが素直で、日本からの遅延も
> 選べるリージョンぶんだけ改善する。

### 動作確認

```bash
curl https://s0ccer-server.onrender.com/health
# {"ok":true,"rooms":0,"players":0,"parties":0}
```

停止中だと最初の1回は時間がかかる。返ってくれば成功。

## 2. Pages を繋ぐ

GitHub リポジトリの
**Settings → Secrets and variables → Actions → Variables タブ → New repository variable**

| Name | Value |
|---|---|
| `SERVER_URL` | `wss://s0ccer-server.onrender.com` |

**`https://` ではなく `wss://`**。ホスト名はそのままで、スキームだけ読み替える。

`Secrets` ではなく **`Variables`** に入れること。ビルド時にクライアントへ埋め込まれる
値なので秘密ではないし、Secrets はビルド出力に出せない。

## 3. 再デプロイ

Variables はビルド時に読まれるので、設定しただけでは反映されない。
**Actions → Deploy client to GitHub Pages → Run workflow** で回すか、何かを push する。

完了したら https://hsgwyuki0429-design.github.io/s0ccer/ を開き、画面上部の表示が
`オフライン（単独）` から `オンライン N人` に変われば成功。

## つまずきやすいところ

**`ws://` を設定してしまった**
Pages は HTTPS なので `ws://` は混在コンテンツとしてブラウザに遮断される。
クライアント側で `wss://` へ自動的に読み替えるようにしてあるが、そもそも
`wss://` で設定するのが正しい。

**「サーバー起動中…」から進まない**
8回試して繋がらなければオフラインへ落ちる。`SERVER_URL` のホスト名が
合っているか、`/health` が返るかを先に確かめる。原因はブラウザのコンソールに出る。

**Blueprint の作成で失敗する**
`render.yaml` の `runtime: docker` が古い Render では `env: docker` の場合がある。
エラーにキー名が出るのでそれに合わせる。

**遊ぶたびに部屋が分かれてしまう**
パーティを組まないと先着順で空き部屋に入る。友達とは画面右上の
**「招待リンク」**を共有すること。同じ部屋・同じチームに入る。

## サーバーを止めたいとき

`SERVER_URL` の Variable を消して Pages を再デプロイすれば、オフライン専用に戻る。
サーバー側のインスタンスも忘れずに停止する（Fly なら `fly apps destroy <名前>`）。

## セキュリティについて

現状、**接続元の制限も認証もしていない。** URL を知っていれば誰でも入れる。

サーバー権威なので位置や得点の改ざんはできないが、部屋を埋められる可能性はある。
友達内で遊ぶ範囲では見合わないコストなので入れていない。公開して困るようなら、
`packages/server/src/index.ts` の `wss.on('connection')` で Origin を見て弾くのが
いちばん手軽。
