# s0ccer ゲームデザイン

トップダウン2D・オンライン対戦サッカー。最大 3v3、eSports 級の操作精度を目標にする。

## 1. 確定した仕様

| 項目 | 決定 |
|---|---|
| 視点 | トップダウン 2D |
| 最大人数 | 6人 = 3v3 |
| 人数調整 | 参加人数が奇数のときのみ AI を1体追加して偶数化 |
| AI の性能 | 人間と完全同一パラメータ（判断ロジックのみ異なる） |
| 部屋 | 先着順で空き部屋に自動振り分け（+ パーティ機能） |
| GK | **なし**（全員フィールドプレイヤー） |
| キャラ性能 | 全員同一 |
| 試合形式 | 時間制（前後半3分）／先取点制 の両対応 |
| 対応端末 | スマホ主軸、PC も対応 |
| クロスプレイ | **あり**（入力デバイスによる有利不利は許容） |
| 想定リージョン | 日本国内のみ（RTT 20〜40ms 前提） |

## 2. 人数とチーム編成

参加人数に対する編成は次のとおり。AI は「奇数のときだけ1体」というルールから一意に決まる。

| 参加人数 | 編成 | AI |
|---|---|---|
| 2 | 1v1 | 0 |
| 3 | 2v2 | 1 |
| 4 | 2v2 | 0 |
| 5 | 3v3 | 1 |
| 6 | 3v3 | 0 |

### AI スロットの引き継ぎ

AI は「空席を埋めているだけ」として扱う。

- 試合中に人間が参加 → **AI の席をそのまま人間が乗っ取る**（試合は中断しない）
- 人間が切断 → **その席を AI が引き継ぐ**（試合は壊れない）
- 再接続 → 自分の席が AI に保持されていれば戻れる

これにより「途中抜けで試合が破綻する」問題と「人数が奇数で待たされる」問題を同時に解消する。

## 3. ピッチとルール

### 寸法

フットサル（40m × 20m）を基準に、3v3 でスカスカにならない範囲へ調整。

- ピッチ: **50m × 32m**
- ゴール幅: **3.2m**
- **ゴールエリア: 各ゴール前の半径 5.5m の半円**

座標系は「ピッチ中央が原点、x が長辺方向、y が短辺方向」。単位はメートル。

### ゴールエリア（GK なしの必須対策）

**GK を置かないと、ゴール前に居座って撃つだけの試合になる。** 3.2m のゴールが常時無人だと、シュートは撃てばほぼ入るからだ。これを防ぐために、ゴール前に**誰も侵入できない半円ゾーン**を設ける。

- 攻撃側・守備側を問わず、**プレイヤーはゴールエリアに入れない**（境界で滑るように押し戻す。ワープはさせない）
- **ボールは自由に通過できる**
- 結果として、全てのシュートは最低 5.5m 離れた位置から撃つことになる

これで「至近距離のごり押し」が消え、シュートの精度・角度・タイミングと、守備側のコース切りが勝負どころになる。GK の役割を、ルールとして空間に置き換えた形。

> **要プレイテスト**: 5.5m という数字と 3.2m のゴール幅は暫定値。実際に蹴ってみて「入りすぎる／入らなすぎる」を見て調整する。両方とも設定値として外に出してある。

### 試合形式

部屋作成時に選択する。

- **時間制**: 前半3分 + 後半3分（ハーフタイムでコートチェンジ）。同点なら引き分け
- **先取点制**: 先に N 点（既定 5点）取ったほうが勝ち。時間制限なし

### その他のルール

- オフサイド **なし**（3v3 では機能しないうえ、判定が事故のもとになる）
- ファウル・カード **なし**（接触は物理的な押し合いのみ）
- ボールがサイドラインを割ったら、**割った地点から相手ボールでリスタート**（スローインは省略し、その場で足元に置く）
- ゴールラインを割ったら（得点以外）、割った側に応じてコーナー／ゴールキック相当の位置からリスタート
- 得点後はセンターサークルからキックオフ

## 4. 操作

### 設計方針

タッチ操作では、指が画面を隠す・触覚がない・入力サンプリングが遅い、という物理的制約から「PC のゲームパッド相当の入力精度」は出せない。

そこで**精度の定義を「入力の細かさ」ではなく「結果の再現性」に置く**。
**同じ操作をしたら必ず同じ球が飛ぶ**ことを保証し、乱数・自動補正を一切入れない。

- **オートエイムなし**
- **オートパスなし**
- **シュートのブレなし**（同じチャージ量・同じ方向なら完全に同じ初速）

### スマホ

- **移動**: 画面左半分の**浮動アナログスティック**。指を置いた場所がその都度の原点になるので、中心ズレによる誤差が出ない。360度・可変半径
- **キック**: 画面右半分を押している間チャージ。**押した時間でパワー、離す瞬間の指の方向で狙う**
  - パワーゲージは画面に常時表示（目で確認できる ＝ 再現性の担保）
  - チャージ 0.6 秒で最大
  - 短いタップ ＝ 低パワー ＝ パス、長押し ＝ 高パワー ＝ シュート（機能としては同一。区別しない）

### PC

- **移動**: WASD / 矢印キー（8方向だが、内部では正規化してアナログ扱い）
- **キック**: マウス左ボタンを押している間チャージ、離すと**マウスカーソル方向**へキック
- ゲームパッド対応は後回し（Phase 5 以降）

### ボールコントロール

ボールは常に物理オブジェクトで、「保持」状態を持たない。

- プレイヤーの**コントロール半径（1.2m）**内にボールがあり、かつプレイヤーが動いているとき、ボールを進行方向へ軽く押し出す ＝ **ドリブル**
- キックはボールへの**撃力（インパルス）**。コントロール半径内にあるときだけ有効
- 相手のドリブル中のボールも、自分のコントロール半径に入れば同じように扱える ＝ **自然な奪い合い**

「ボールを持つ」という状態を作らないことで、奪取判定の理不尽さが消え、常に物理で説明がつくようになる。

## 5. パーティとマッチメイキング

「先着順で自動振り分け」だけだと、友達同士で入っても別々の部屋・別々のチームに散る。これを防ぐためパーティを併設する。

- **ソロ**: キューに入る → 空き部屋に先着順で自動振り分け
- **パーティ**: 友達を招待（招待コード）→ パーティ単位でキューに入る → **必ず同じ部屋・同じチーム**に入る
- パーティ上限は **3人**（＝1チーム分）。4人以上は対戦を分ける必要が出て複雑になるので上限を切る

部屋は最大6人。埋まっていなければ試合中でも途中参加でき、AI の席を引き継ぐ。

## 6. 開発フェーズ

順に積む。各フェーズの終わりに「遊べる状態」を作る。

| Phase | 内容 | 状態 |
|---|---|---|
| **1** | ローカル1人プロトタイプ。物理・操作・描画・ゴール判定 | ✅ 完了 |
| 2 | サーバー権威 + 2人オンライン同期（クライアント予測 / リコンシリエーション / 補間） | 未着手 |
| 3 | 部屋・パーティ・マッチメイキング | 未着手 |
| 4 | AI（人間と同一の入力しか出せない制約つき） | 未着手 |
| 5 | 試合形式（時間制／先取点制）、リスタート、スコア、UI | 未着手 |

**Phase 1 で操作感を確定させてから Phase 2 に進む。** ネットコードは操作感を「保つ」ための技術であって、「作る」ための技術ではないため、土台の手触りが悪いままオンライン化しても意味がない。
