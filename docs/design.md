# s0ccer ゲームデザイン

トップダウン2D・オンライン対戦サッカー。最大 3v3、eSports 級の操作精度を目標にする。

## 1. 確定した仕様

| 項目 | 決定 |
|---|---|
| 視点 | トップダウン 2D |
| 最大人数 | 6人 = 3v3 |
| 人数調整 | 足りない側を AI が埋めて両チームを常に同数にする |
| AI の性能 | 人間と完全同一パラメータ（判断ロジックのみ異なる） |
| 部屋 | 先着順で空き部屋に自動振り分け（+ パーティ機能） |
| GK | 各チーム1人。ランダム選出、ボタンで交代可。**自陣ゴールエリアに入れるのは GK だけ** |
| キャラ性能 | 全員同一 |
| 試合形式 | 時間制（前後半3分）／先取点制 の両対応 |
| 対応端末 | スマホ主軸、PC も対応 |
| クロスプレイ | **あり**（入力デバイスによる有利不利は許容） |
| 想定リージョン | 日本国内のみ（RTT 20〜40ms 前提） |

## 2. 人数とチーム編成

参加人数に対する編成と AI の数は「7. AI」を参照。AI は空席を埋めているだけとして扱うので、
途中参加・途中抜けのどちらでも試合は壊れない。

## 3. ピッチとルール

### 寸法

フットサル（40m × 20m）を基準に、3v3 でスカスカにならない範囲へ調整。

- ピッチ: **50m × 32m**
- ゴール幅: **3.2m**
- ゴールエリア: 各ゴール前の半径 **5.5m** の半円

座標系は「ピッチ中央が原点、x が長辺方向、y が短辺方向」。単位はメートル。

### ゴールキーパーとゴールエリア

各チームに **GK が1人**いる。ただし GK は特殊能力を持つ別の駒ではない。
**能力は他の選手と完全に同一で、違いは「自陣のゴールエリアに入れる」ことだけ。**

- **ゴールエリア**: 各ゴール前の半径 5.5m の半円
- **入れるのは自陣の GK だけ。** 味方のフィールドプレイヤーも、相手も入れない
- GK がエリアから**出るのは自由**
- **ボールは誰の妨げも受けず自由に通過する**

これにより、フィールドプレイヤーのシュートは常に最低 5.5m 離れた位置から撃つことになる。至近距離のごり押しが消え、シュートの精度・角度・タイミングと、守備側のコース切りが勝負どころになる。

#### GK の決め方と交代

- 試合開始時、各チームから**ランダムに1人**が GK に選ばれる
- **誰でも画面右上のボタン（PC は G キー）で GK を代われる。** 押した本人が GK になり、それまでの GK は通常の選手に戻る＝**入れ替わる**
- GK が退出したら、残りから自動で選び直される

**抽選はサーバー側でしか行わない。** `step()` に乱数が入ると決定論が壊れ、クライアント予測がサーバーと一致しなくなる。一方、ボタンによる交代は乱数を使わないので `step()` の中で処理でき、クライアントも同じ結果を予測できる。

> **要プレイテスト**: エリア半径 5.5m とゴール幅 3.2m は暫定値。GK が1人いる前提で「入りすぎ／入らなすぎ」を見て調整する。両方とも設定値として外に出してある。

### その他のルール

- オフサイド **なし**（3v3 では機能しないうえ、判定が事故のもとになる）
- ファウル・カード **なし**（接触は物理的な押し合いのみ）
- 得点後はセンターサークルからキックオフ

試合形式とライン割れの扱いは「8. 試合形式」を参照。

## 4. 操作

### 設計方針

タッチ操作では、指が画面を隠す・触覚がない・入力サンプリングが遅い、という物理的制約から「PC のゲームパッド相当の入力精度」は出せない。

そこで**精度の定義を「入力の細かさ」ではなく「結果の再現性」に置く**。
**同じ操作をしたら必ず同じ球が飛ぶ**ことを保証し、乱数・自動補正を一切入れない。

- **オートエイムなし**
- **オートパスなし**
- **シュートのブレなし**（同じチャージ量・同じ方向なら完全に同じ初速）

### スマホ

- **移動**: 画面左半分の**浮動アナログスティック**。指を置いた場所がその都度の原点になるので、中心ズレによる誤差が出ない。360度・可変半径
- **キック**: 画面右半分を押している間チャージ。**離す瞬間の指の方向で狙い、倒し量で強さを決める**
  - パワーゲージは画面に常時表示（目で確認できる ＝ 再現性の担保）
  - チャージ 0.6 秒で最大
  - 短いタップ ＝ 低パワー ＝ パス、長押し ＝ 高パワー ＝ シュート（機能としては同一。区別しない）

#### 倒し量を強さの軸にする理由

スマホでは狙いを定めるのに指をドラッグする必要があり、**そのドラッグにかかる時間ぶんチャージが溜まってしまう**。つまり「丁寧に狙う」と「強く蹴る」が時間軸で結合していて、**慎重に狙うと必ず強い球になる**という不本意な制約が生まれていた。

そこで倒し量を独立した強さの軸にして、狙いと強さを切り離す。

```
初速 = KICK_SPEED_MIN + (KICK_SPEED_MAX - KICK_SPEED_MIN) × チャージ量 × 倒し量
```

フルチャージのままでも、倒し量を抑えれば弱い球が撃てる。倒し切れば従来どおり最大速度が出るので、既存の手触りは変わらない。乱数は入らないので、**同じチャージ量・同じ倒し量なら必ず同じ球が飛ぶ**という保証も維持される。

### PC

- **移動**: WASD / 矢印キー（8方向だが、内部では正規化してアナログ扱い）
- **キック**: マウス左ボタンを押している間チャージ、離すと**マウスカーソル方向**へキック
- **倒し量による強さの調整はない**（常に最大倍率）。マウスは狙いが一瞬で定まるため、上記の「狙う時間＝チャージ時間」問題が起きず、チャージ時間だけで強さを制御できるため
- ゲームパッド対応は未着手

### チャージ中の減速

チャージ中は最大速度が落ちる。**チャージ量に比例**し、フルチャージで **-45%**（7.0 → 3.85 m/s）。

一律に減速させると軽いパスのたびに足が止まって窮屈になるので、比例させている。軽く蹴るぶんにはほぼ減速せず、強い球を撃つときだけ大きく動きが拘束される ＝ リスクとリターンが釣り合う。

### ボールコントロール

ボールは常に物理オブジェクトで、「保持」状態を持たない。

- プレイヤーの**コントロール半径（1.2m）**内にボールがあり、かつプレイヤーが動いているとき、ボールを進行方向へ軽く押し出す ＝ **ドリブル**
- キックはボールへの**撃力（インパルス）**。コントロール半径内にあるときだけ有効
- 相手のドリブル中のボールも、自分のコントロール半径に入れば同じように扱える ＝ **自然な奪い合い**

「ボールを持つ」という状態を作らないことで、奪取判定の理不尽さが消え、常に物理で説明がつくようになる。

## 5. パーティとマッチメイキング

「先着順で自動振り分け」だけだと、友達同士で入っても別々の部屋・別々のチームに散る。これを防ぐためパーティを併設する。

- **ソロ**: キューに入る → 空き部屋に先着順で自動振り分け
- **パーティ**: 友達を招待（招待コード）→ パーティ単位でキューに入る → **必ず同じ部屋・同じチーム**に入る
- パーティ上限は **3人**（＝1チーム分）。4人以上は対戦を分ける必要が出て複雑になるので上限を切る

部屋は最大6人。埋まっていなければ試合中でも途中参加でき、AI の席を引き継ぐ。

## 6. 開発フェーズ

順に積む。各フェーズの終わりに「遊べる状態」を作る。

| Phase | 内容 | 状態 |
|---|---|---|
| **1** | ローカル1人プロトタイプ。物理・操作・描画・ゴール判定 | ✅ 完了 |
| **2** | サーバー権威 + オンライン同期（クライアント予測 / リコンシリエーション） | ✅ 完了 |
| **3** | 部屋・パーティ・マッチメイキング、画面外インジケータ | ✅ 完了 |
| **4** | AI（人間と同一の入力しか出せない制約つき） | ✅ 完了 |
| **5** | 試合形式（時間制／先取点制）、リスタート、スコア、UI | ✅ 完了 |

**Phase 1 で操作感を確定させてから Phase 2 に進む。** ネットコードは操作感を「保つ」ための技術であって、「作る」ための技術ではないため、土台の手触りが悪いままオンライン化しても意味がない。

### 現在の制限

- 試合形式（時間制／先取点制）は**サーバー側の既定値のみ**。部屋ごとに選ぶ UI はまだない
- AI の強さは1段階のみ。難易度調整はできない
- ゲームパッド未対応

## 7. AI

人数が奇数のときや、人間が抜けた席を AI が埋める。

**AI は `PlayerInput` しか出力できない。** 位置を直接書き換えることも、人間より速く動くこともできない。人間とまったく同じ物理・同じ上限で動き、違うのは判断ロジックだけ。「AI と人間は同一パラメータ」という要件を、実装の構造そのもので保証している。

### 人数の決まり方

規則は「**両チームを常に同数にする**」の一点。人間の多いほうの人数に揃え、足りない側を AI で埋める。

| 状況 | 編成 | AI |
|---|---|---|
| 1人 | 1v1 | 1 |
| 2人（別チーム） | 1v1 | 0 |
| 2人（同じパーティ＝同じチーム） | 2v2 | 2 |
| 3人 | 2v2 | 1 |
| 5人 | 3v3 | 1 |
| 6人 | 3v3 | 0 |

「参加人数が奇数のときだけ AI を1体」というのは、人間が両チームに均等に散っている場合のこの式の帰結。パーティは全員が同じチームに入るので人間は均等に散らず、人数だけで数えると 2v1 のような壊れた試合になってしまう。

### 席の引き継ぎ

- 人間が参加 → **AI の席をそのまま人間が乗っ取る**（試合は中断しない）
- 人間が切断 → 上の計算の結果として **AI がその席を埋める**

## 8. 試合形式

部屋ごとに次のどちらかで進行する。

- **時間制**（既定）: 前半3分 + 後半3分。ハーフタイムでコートチェンジ。同点なら引き分け
- **先取点制**: 先に N 点（既定5点）取ったほうが勝ち

### フェーズ

| フェーズ | 内容 |
|---|---|
| `countdown` | 開始前・得点後の静止（1.5秒）。位置がリセットされ、**操作を受け付けない** |
| `playing` | 通常プレー |
| `halftime` | ハーフタイム（4秒）。明けにコートチェンジ |
| `finished` | 試合終了（8秒）。結果を出してから自動で次の試合へ |

GK の交代だけは、どのフェーズでも受け付ける。UI の操作であってプレーではないため。

### ライン割れ

ボールがラインを割ったら、**割った側の相手ボール**で再開する。

- ボールはラインから 1m 内側に置かれ、静止する
- その後 **1.2秒間、割った側のチームはボールに触れない**（ドリブルもキックもできない）

スローインの動作は省略している。3v3 のテンポを優先し、止まる時間を最小限にするため。

> **要プレイテスト**: 50m × 32m のピッチで 3v3 だと、ボールが外に出る頻度が高い。ラリーが途切れすぎるようなら、フットサルの board のように**サイドラインを壁にする**選択肢もある。`sim.ts` の該当箇所を跳ね返しに戻すだけで切り替えられる。

## 9. 画面外の把握

3v3 のピッチは画面に収まらないので、画面外にいる選手とボールを**画面端の三角形**で示す。チーム色で塗り分け、ボールは白。

ミニマップより視線移動が少なく、操作中でも把握しやすいと判断した。
