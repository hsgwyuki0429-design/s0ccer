# s0ccer

友達と遊ぶための、トップダウン 2D のオンライン対戦サッカー。最大 3v3。
スマホ主軸・PC 対応・クロスプレイあり。

状態で遊べる。

## 動かす

```bash
npm install
npm run dev      # サーバー(:8787) とクライアント(:5173) を同時に起動
```

表示された URL をブラウザで開く。`--host` が有効なので、**同一 LAN のスマホからも
実機で確認できる**（ターミナルに出る Network の URL を開く）。開発サーバー経由なら
同じホストの `:8787` へ自動で繋ぎに行くので、設定なしでオンライン対戦になる。

```bash
npm run dev:client   # クライアントだけ
npm run dev:server   # サーバーだけ
npm test             # シミュレーションとプロトコルのテスト
npm run check        # 型チェック
npm run build        # 本番ビルド
```

### 接続先の指定

クライアントは次の順で接続先を決める。

1. `?server=wss://...` クエリパラメータ（静的ホスティングから繋ぐとき）
2. ビルド時の `VITE_SERVER_URL` 環境変数
3. 開発サーバーなら同じホストの `:8787`
4. どれもなければ**オフライン（単独プレイ）**

`?offline=1` を付けると強制的にオフラインになる。サーバーに繋がらなかった場合も
オフラインへ落ちるので、静的ビルドだけでも操作感の確認はできる。

## 操作

**スマホ**
- 画面左半分: 浮動アナログスティックで移動（指を置いた場所が原点）
- 画面右半分: 長押しでチャージ → **離す瞬間の指の方向**へキック。**倒し量が強さ**

**PC**
- WASD / 矢印キー: 移動
- マウス長押し: チャージ → **カーソル方向**へキック
- G: キーパー交代 ／ R: リセット（オフラインのみ）

**画面右上のボタン**
- 「キーパーになる」: 押した人が GK になり、それまでの GK と入れ替わる
- 「招待リンク」: 自分のパーティに友達を招くリンクをコピー／共有する

**チャージ中は足が遅くなる**（チャージ量に比例、フルで -45%）。強い球には拘束が伴う。

スマホで倒し量が強さになっているのは、**狙いのドラッグにかかる時間ぶんチャージが
溜まってしまい、丁寧に狙うと必ず強い球になる**問題を切り離すため。フルチャージの
ままでも倒し量を抑えれば弱い球が撃てる。

オートエイム・オートパス・シュートのブレは**一切入れていない**。同じチャージ量・
同じ倒し量で同じ方向へ蹴れば、必ず同じ球が飛ぶ。画面のパワーゲージと狙いの線は
実際の初速と同じ式で描いているので、表示と実物が食い違うことはない。

## 設計

- [docs/design.md](docs/design.md) — ゲームデザイン（ルール、人数、操作、マッチメイキング）
- [docs/netcode.md](docs/netcode.md) — ネットコード設計
- [docs/deploy.md](docs/deploy.md) — サーバーのデプロイと Pages との接続

**GK は特殊能力を持つ別の駒ではない。** 能力は他の選手と完全に同一で、違いは
「自陣のゴール前の半円エリアに入れる」ことだけ。出るのも自由で、誰でもボタンで代われる。
フィールドプレイヤーはこのエリアに入れないので、シュートは必ず 5.5m 以上離れた位置からになる。

**AI は `PlayerInput` しか出力できない。** 位置を直接書き換えることも、人間より速く動くことも
できない構造にしてある。「AI と人間は同一パラメータ」を実装の形で保証するため。

また、**ボールを含む世界全体をクライアント予測している**。ボールだけ補間表示にすると
キックの反応が RTT + 補間遅延ぶん遅れ、サッカーとして成立しないため。詳細は netcode.md。

## デバッグ表示

画面左上に常時出している。体感の議論を主観でやらないため。

| 表示 | 意味 |
|---|---|
| `rtt` | 往復遅延（ms） |
| `tick (+n)` | ローカルティックと未確認入力の数 |
| `queue` | サーバー側の未処理入力キューの深さ。1〜3 が正常 |
| `fix` | リコンシリエーションの補正量。**0.0cm なら予測がサーバーと完全一致** |

## 友達と遊ぶ

1. 誰か1人がページを開く
2. 画面右上の**「招待リンク」**を押してリンクを共有する
3. 友達がそのリンクを開くと、**同じ部屋・同じチーム**に入る

パーティの上限は3人（＝1チーム分）。パーティを組まない人は先着順で空き部屋へ自動で
振り分けられ、足りない席は AI が埋める。

ただし**これにはゲームサーバーが要る**。手順は [docs/deploy.md](docs/deploy.md) に
まとめてある。サーバーを立てて GitHub の Variables に `SERVER_URL` を設定すれば、
GitHub Pages が自動でそこへ繋がる。未設定ならオフライン（単独）で動くので、
サーバーを止めてもページが壊れることはない。

## 構成

```
packages/
├─ shared/   決定論シミュレーション + 試合進行 + プロトコル（唯一の真実）
├─ server/   Node + WebSocket（部屋・ロビー・AI、60Hz sim / 30Hz snapshot）
└─ client/   Vite + Canvas のクライアント
```

`shared` はビルド成果物ではなく **ソースを直接** 参照している。サーバーとクライアントが
同じ物理コードを読み込むための構成で、ここが分岐すると予測が常時ズレる。

サーバーは `../../shared/src/...` と相対パスで読んでいる。Node の型ストリッピングが
`node_modules` 配下の `.ts` を処理しないため、ワークスペース名では解決できない。
